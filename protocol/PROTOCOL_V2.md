# AXIOM-X V2 preregistered protocol

Status: **FROZEN BEFORE ANY V2 HELD-OUT MODEL RUN**. The freeze commit is recorded in `protocol/FREEZE.json`. Any later change to primary hypotheses, sampling, or primary metrics requires a dated amendment and becomes exploratory.

## Scope and research questions

The estimand is false certification among bounded finite-domain counting problems, not general mathematical reasoning.

- RQ1: without Gold, can independent generation detect naturally occurring natural-language-to-specification errors?
- RQ2: does B2 reduce false certification relative to B0?
- RQ3: does B2 add value beyond B1 cheap checks and B3 back-translation?
- RQ4: how does detection vary by prespecified error category?
- RQ5: what coverage, abstention, false-rejection, latency, token, and monetary costs accompany any reduction?
- RQ6: do Primary and Secondary make common specification errors?

Null-compatible hypotheses: B2 may have no lower false-certification rate than B0/B1/B3; it may only trade coverage for apparent safety; correlated errors may remain undetected.

## Dataset and split

The V2 authored benchmark contains 12 Development and 40 Held-out English finite-domain counting problems. Problems are generated from a recorded template/parameter ledger, then manually readable as standalone questions. The strata are integer domains, order/bounds, exact/at-least/at-most counts, distinctness, finite digit strings, conjunctions, and negation. Exact duplicate text, identical parameter tuples, V1 private questions, and unsupported operations are excluded. Development templates/parameters are fixed first; Held-out uses disjoint IDs and parameter tuples. “Held-out” means held out from this project's prompt tuning, not unseen in model training.

Source: original AXIOM-X V2 benchmark authored with Codex assistance on 2026-10-23; no third-party question text is claimed. Gold is generated by the same bounded DSL and must therefore be independently human-reviewed before confirmatory publication.

The synthetic mechanism set contains 16 prespecified mutations, kept separate from natural model outputs. It cannot increase the natural-error denominator.

## Systems and fixed settings

- Primary and Secondary: separate stateless API calls, temperature 0, JSON-only output, no retry after a valid HTTP response; one retry is allowed only for transport/429/5xx failure and must be logged.
- Models: supplied explicitly at run time and recorded verbatim. Primary and Secondary may be the same model version but are never described as statistically independent.
- Prompts: `prompts/v2_primary.txt` SHA-256 `b253715a75c8e23641445f9d88de79096bba2cc4f0c8d363ca1c6d8e34b4f108`; `prompts/v2_secondary.txt` SHA-256 `8c925c3ce14171439f6544ada98aa15a915bc35a02a3c448e110b66237d923b2`.
- Z3/model-enumeration timeout: 5,000 ms per specification/comparison. Search space is capped at 1,000,000 assignments.
- Formal test execution: exactly one full 40-problem Held-out run after Development debugging and freeze. Failed, timed-out, and unparsable rows remain in the denominator as ABSTAIN.
- Seed: `20261023` for resampling. Deterministic decoding has no claimed model seed unless the provider records one.

## Gold-blind flow

Prediction reads only `data/v2/public/*.json`. Primary and Secondary each receive only `problem_id`, `problem_text`, and their fixed system prompt. Secondary receives no Primary object. B0/B1/B2/B3 operate before any Gold path is opened. Prediction JSONL is written and SHA-256 frozen in a receipt. The separate evaluator refuses missing, altered, or ID-mismatched prediction files and only then reads `data/v2/gold/*.json`.

This is capability/interface isolation for a remote model with no local tools. It is not an OS security boundary against malicious local Python code. The analyst (Codex/user) is not blinded to the existence or later contents of Gold. Independent generation is operational, not statistical independence.

## Compared groups

- B0: Primary specification + Z3; ACCEPT on complete solver result, otherwise ABSTAIN.
- B1: same Primary and answer plus fixed low-cost structural rules; explicit violation REJECTs, incomplete evidence ABSTAINs.
- B2: same Primary plus a separately called Secondary and Gold-blind solution-set audit; equivalent sets and solver agreement ACCEPT, a symmetric-difference witness or answer inconsistency REJECT, unsupported mapping/timeout/failure ABSTAIN.
- B3: deterministic specification back-translation plus fixed semantic checks against the original wording; mismatch REJECTs, insufficient evidence ABSTAINs.

All groups share the exact same Primary generation. B2 uses an additional model call; raw and cost-aware comparisons are both reported.

## Labels

After freeze, Gold evaluation labels separately:

- Specification Faithfulness: CORRECT only when the Primary and Gold specifications have equal finite solution sets under an identical variable/domain mapping; ERROR on a witnessed set difference; UNKNOWN otherwise.
- Answer Correctness: CORRECT if the candidate count equals Gold; ERROR if unequal; UNKNOWN if missing.

A coincidentally correct answer does not repair an erroneous specification. Human semantic review is independent of these automatic equivalence labels and remains PENDING unless a real reviewer supplies a signed/dated ledger.

## Primary metrics

For both specification and answer error:

- False Certification Rate = erroneous candidates ACCEPTed / erroneous labelled candidates.
- Acceptance Coverage = ACCEPT / all rows.
- Abstention Rate = ABSTAIN / all rows.
- Error Detection Rate = erroneous candidates REJECTed / erroneous labelled candidates.
- False Rejection Rate = correct candidates REJECTed / correct labelled candidates.
- Selective Risk = erroneous ACCEPTed / labelled ACCEPTed.
- Error Rate = erroneous / labelled.

Every metric reports numerator and denominator. Zero denominators are `N/A`, never 0%. Wilson 95% intervals are descriptive. Pairwise B0–B3 comparisons use the same cases; exact McNemar tests on discordant specification-error false certifications are exploratory. No multiple-testing-adjusted confirmatory claim is planned. If repeated generations are later added, resampling and inference must cluster by base problem.

## Error analysis

Prespecified categories: omitted condition, reversed condition, boundary error, domain error, exactly/at-least/at-most confusion, combinatorial restriction, common Primary/Secondary error, inequivalent specifications with equal answers, satisfiable wrong specification, and false rejection. Only observed cases are described as findings.

## Stops, exclusions, and budget

Stop before Held-out when Gold-isolation tests fail, the public split is contaminated, provenance cannot be traced, labels cannot be determined, outputs cannot be frozen, required real model access is unavailable, or projected incremental API expense exceeds USD 10. No row is excluded after generation except a pre-run duplicate/unsupported-item check; all provider and parser failures are retained. Existing lower configured budget overrides USD 10.

If naturally occurring errors are too few for comparison, the report must state: “Insufficient naturally occurring errors to establish comparative detection effectiveness.” Synthetic cases remain separate. Negative results, common-mode errors, and uncompleted human review are disclosed.

## Limitations fixed in advance

The 40-problem authored sample is small and narrow; Gold construction can be wrong; model versions drift; deterministic temperature does not guarantee repeatability; exact-name mapping can increase abstention; prompt/template regularity may favor rules; and no result supports open-domain or population-wide reliability.
